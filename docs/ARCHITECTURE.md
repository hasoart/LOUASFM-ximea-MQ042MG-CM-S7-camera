# Архитектура копии XIMEA

Копия создана из Basler-репозитория `f651ea4` через локальное клонирование;
пять исходных checkpoint-коммитов сохранены. Соседняя версия Basler и
ThuliumBB не редактируются. Камерный SDK заменён, а независимые части
просмотра, записи и UDP сохранены. Старые монолитные сканеры/анализаторы
остаются в `legacy/` и не импортируются при запуске.

## Что заменено

- Удалён активный pypylon-драйвер и зависимость pypylon.
- Добавлен `cameras/ximea_camera.py` с xiAPI, USB3, выбором по serial,
  экспозицией/gain/битностью/ROI/триггером, FIFO и проверкой номера кадра.
- Добавлен `sdk_runtime.py`: поиск официального Python-модуля SDK и DLL,
  локальный путь установки, понятная ошибка при отсутствующем native SDK.
  Модуль производителя не переписывается и не патчится.
- Убраны IP камеры, ForceIP и GigE packet/delay из модели настроек и GUI;
  IP/UDP BeagleBone сохранены в отдельной вкладке.
- Добавлен выбор АЦП 8/10 и Mono8/Mono16/Raw8/Raw16; GPIO называется GPI1.
- У конфигурации schema_version=2; старый runtime JSON Basler не используется.
- Документация/справка/упаковка относятся к MQ042MG-CM-S7 и XIMEA SDK.

## Основные слои

| Модуль в `louasfm_camera/` | Задача |
| --- | --- |
| `models.py`, `config.py` | Общие настройки, Frame, проверка значений, атомарный JSON и backup |
| `sdk_runtime.py` | Поиск unmodified официального SDK без системной установки из приложения |
| `cameras/base.py` | Минимальный интерфейс и фабрика XIMEA/demo |
| `cameras/ximea_camera.py` | Документированные методы xiAPI, без Qt |
| `cameras/simulated.py` | Синтетический источник; внешние импульсы только по явной команде |
| `services/acquisition.py` | Один владеющий камерой поток, состояния, снимок/серия, graceful close |
| `services/storage.py` | Ограниченная очередь TIFF/PNG + JSON, без Qt |
| `services/beaglebone.py` | UDP 9998, строгий парсер, snapshot контекста; без Qt |
| `services/analysis.py` | ROI, статистика, профили в единицах пикселей |
| `ui/` | Поля и действия пользователя, изображение/ROI, схема и журнал |

Ни один аппаратный драйвер не создаётся при импорте GUI. Для `--demo` не
требуется ни SDK, ни USB, ни плата. Все операции конкретного устройства,
включая поиск/открытие, конфигурацию и get_image, идут в camera-owner.
GUI получает небольшие Qt-сигналы, а preview читает один latest-frame slot
раз в 100 мс, чтобы не накапливать очередь полных изображений.

## Контракт xiAPI

Реальные имена параметров и методы сверены с официальным Python SDK 4.34.00
из Windows и Linux-пакетов. В отличие от GenICam, диапазоны запрашиваются
`param:min`, `param:max`, `param:inc`; enum min/max возвращаются строками,
например XI_GPI_PORT1. Ошибки необязательной функции отделены от ошибок
доступа/USB; только статус 10 (XI_TIMEOUT) считается нормальным ожиданием.

`imgdataformat` может автоматически менять bit-depth. Поэтому формат
ставится раньше sensor_bit_depth/output_bit_depth, а фактическая цепочка
попадает в JSON. При считывании перед обращением к SDK-массиву проверяются
размер/число байт; затем массив копируется в собственную память. После этого
следующий get_image/закрытие не инвалидируют сохранённый Frame.

SDK работает с `XI_BP_SAFE`, `recent_frame=0`, очередью до 16 buffers.
В пределах одного start проверяется последовательность uint32 nframe,
включая переход через 2^32. При новом start эталон сбрасывается: смена
параметров сама может сбрасывать счётчик. Такой контроль не обнаруживает
любой отвергнутый сенсором триггер и не гарантирует учёт потерь до первого
полученного кадра.

## Запись и завершение

Передача в image-writer не блокирует основной GUI. Очередь на восемь кадров
ограничивает RAM; переполнение, ошибка диска, неверный буфер или разрыв nframe
останавливают серию с ошибкой. Принятые задания дописываются при закрытии.
Отклонённая повторная команда start не прерывает уже идущую запись.
После частичной ошибки конфигурации устройство закрывается, чтобы не
показывать старые параметры как успешно применённые.

Файлы сохраняются без контрастной нормализации; уникальное имя содержит UTC,
frame_id и UUID. Изображение/JSON пишутся во временные файлы с flush/fsync,
затем переименовываются. Пара файлов не является общей транзакцией: при
отказе второго rename возможен снимок без JSON, при этом ошибка не скрывается.
Принудительное завершение процесса или потеря питания не выполняет cleanup.

Конфиг и backup также пишутся через временный файл + os.replace. Несколько
независимых запусков должны использовать отдельные --config: межпроцессной
блокировки одного JSON нет. SDK-путь хранится в отдельном ignored marker,
поэтому копия не получает чужие Windows/Linux-пути при переносе исходников.

## Границы проверки

Тестовый `fake_xiapi.py` следует официальным сигнатурам, перечислениям и
правилам типов, но не эмулирует реальную камеру, USB и каждый режим сенсора.
Загрузка native-библиотеки с перечислением 0 устройств проверена отдельно.
Физическое устройство и Windows-исполнение ещё нужно проверить на стенде.
Новые сканеры, atom calibration, HDR-калибровка, управление GPO, все SDK
counters/events и строгая аппаратная привязка кадра к циклу в эту версию
не входят.
