# Проверки XIMEA-версии — 08.11.2026

Среда: Linux x86_64, Python 3.11.15, отдельный `.venv` этой копии.
Физической XIMEA и Windows-компьютера в этой среде нет.

10.11.2026 пользователь сообщил об успешной работе большей части функций на
своём стенде XIMEA. Полный перечень проверенных режимов/версия SDK пока не
уточнены. Ниже описаны воспроизводимые проверки, выполненные агентом локально.

## Автоматические проверки

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check louasfm_camera tests scripts
.venv/bin/python -m compileall -q louasfm_camera scripts main.py
bash -n run_linux.sh
```

**56 тестов** проверяют хранение конфигурации/backup и отказ от Basler JSON,
исходные uint8/uint16 в TIFF/PNG, уникальные имена, очередь записи и ошибки
диска, graceful drain, UDP Hi/Close и схему больше 1024 байт, график фронтов,
демонстрацию и полный GUI. Добавлены проверки XIMEA:

- Поиск без открытия/перенастройки устройств, выбор serial при нескольких
  камерах; байтовые device info из официального интерфейса.
- Enum min/max как строки, числовые min/max/inc, округление ROI и экспозиции.
- Все три источника захвата, обе полярности, GPI_TRIGGER, FRAME_START,
  ограничитель FPS и его отключение.
- Фактические bit-depth после автоматических изменений imgdataformat;
  копирование переиспользуемого буфера, timestamp в микросекундах.
- XI_TIMEOUT как нормальное ожидание; ошибки USB/права/остановка/No image
  остаются ошибками.
- Предварительная проверка неполного буфера, разрыв nframe, uint32 wrap,
  сброс контроля при новом start.
- Неподдерживаемый requested binning не подменяется молча.
- Поиск Python-пакета SDK в каталоге с пробелами, локальный marker пути,
  понятная ошибка отсутствующей native-библиотеки.
- Полный GUI через XimeaCamera + fake SDK: Raw16-снимок, запись, возврат
  прежнего External и отсутствие IP/ForceIP/GigE-полей.

Fake следует сигнатурам и типам **официального SDK 4.34.00**, но не является
официальным эмулятором XIMEA и не доказывает физическую корректность USB/GPIO.
Тесты не открывают реальные устройства и BeagleBone. Отдельно прошёл обычный
Linux/xcb запуск окна и headless запуск без SDK:

```bash
./run_linux.sh --demo
QT_QPA_PLATFORM=offscreen .venv/bin/python -m louasfm_camera --demo --smoke-seconds 2
```

## Проверка производителя SDK

Скачаны неизменённые официальные пакеты:

- Windows LTS 4.34.00: структура архива просмотрена без запуска EXE; проверены
  10 используемых методов Camera/Image, Python v3-модуль и пути 64-bit DLL.
- Linux LTS 4.34.00: пакет распакован, системная установка не выполнялась.
  `libm3api.so.2` успешно загружена напрямую; `xiGetNumberDevices` вернул 0
  (XI_OK), число устройств 0. Воспроизводимая проверка:

  ```bash
  .venv/bin/python scripts/diagnose.py --native-library vendor/sdk/extracted/package/api/X64/libm3api.so.2
  ```

Вызовы configure/get_image на физической камере не выполнялись. На Windows
программа и установщик не запускались. Это ограничения проверки, а не
заявление о готовности конкретного USB-контроллера/драйвера/проводки.

## Первая проверка на Windows с камерой

1. Установить Python 3.11 x64, XIMEA SDK с драйвером USB3 и Python v3,
   requirements.txt; зарегистрировать SDK через configure_ximea_sdk.py --check.
2. Проверить камеру в xiCOP/xiCamTool, затем закрыть их захват. Записать точную
   модель/суффикс и serial; если это не S7, заново сверить I/O по её руководству.
3. Подключиться в приложении. Начать с Mono8, binning 1, экспозиции 1 мс,
   полного кадра, минимального gain. Выполнить «Снять и сохранить» из Stop.
4. Повторить Raw16; проверить TIFF/JSON, битность АЦП и container dtype,
   фактические размеры. Проверить перезапуск с сохранением настроек.
5. Free run с лимитом 10 FPS: несколько секунд просмотра, затем короткая
   запись на локальный диск. После Stop дождаться очереди; сопоставить
   получено/сохранено при записи каждого кадра.
6. **До аппаратного триггера проверить согласующий драйвер:** HIGH >4 В,
   ток >2 мА по S7 manual; прямой 3,3-В GPIO не подходит. Проверить Binder
   pin 1 GND / 3 IN и правильную ориентацию.
7. External + GPI1, выбрать edge. Без импульса окно должно оставаться
   отзывчивым. Подать известное число редких импульсов, сравнить файлы и счётчик.
8. Затем проверить реальную частоту опыта, задержки и окна экспозиции/света.
   Не выводить максимальную частоту Raw16 из рекламных 90 FPS Mono8.
9. Открыть веб-интерфейс BBMain, подключить UDP 9998, сравнить D0/D2 со схемой
   и осциллографом. Полный цикл с пустыми стадиями не выводится из конца графика.
10. Проверить Stop/Close во время серии и повторное открытие камеры. Закрытие
    приложения камеры не выключает выходы BeagleBone.

## Переносимые архивы

После коммита исходников:

```bash
.venv/bin/python scripts/make_release.py --with-wheels --with-sdk
```

Архив программы содержит исходники, legacy, русские инструкции и официальные
руководства; без `.venv`, runtime state, кадров и `.git`. Отдельный архив
`windows-python311-sdk-and-wheels.zip` содержит шесть Python wheels и
оригинальный Windows SDK EXE. Оба распаковываются с общим верхним каталогом
проекта; для EXE требуется отдельный обычный запуск установщика оператором.
Для архивов и внешних файлов сохраняются SHA-256. Git-история есть в локальном
репозитории и дополнительном `camera-history.bundle`.
