# Проверки первой версии

Проверка выполнена 04.11.2026 на Linux x86_64, Python 3.11.15 в отдельном venv.
Целевая физическая Basler и Windows-компьютер из этой среды недоступны.

## Что проверено автоматически

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check louasfm_camera tests scripts
.venv/bin/python -m compileall -q louasfm_camera scripts main.py
bash -n run_linux.sh
```

35 тестов покрывают:

- сохранение/загрузку конфигурации и backup, отказ при повреждённом JSON;
- валидацию настроек, диапазоны и старые GenICam-имена;
- Mono8/Mono12 через официальный **pylon Camera Emulation**, программный
  триггер, ожидание без импульса, повторную настройку ROI/binning;
- копию кадра, которая остаётся валидной после Release и следующего кадра;
- TIFF/PNG uint8/uint16 с точным сохранением исходных чисел, уникальные имена
  и JSON-контекст;
- явный отказ при переполнении дисковой очереди и ошибке записи;
- внешние импульсы демонстрационной камеры без самопроизвольных кадров;
- остановку записи при отказе диска, обработку повторной команды start без
  прерывания текущей записи;
- временный Software-снимок из остановленного External, возврат настроек;
- снимок при идущем External, который ждёт физический импульс;
- bounded latest-frame preview вместо неограниченной очереди GUI-кадров;
- текущие сообщения ThuliumBB, схему длиннее 1024 байт, Hi/Close через реальный
  локальный UDP socket, повреждённый пакет без смерти приёмника;
- фронты периодической схемы, включая отсутствие фронтов у постоянно HIGH;
- полный Qt-интерфейс: подключение, настройку, снимок, ROI, график схемы,
  скриншот и завершение потоков с дописыванием принятых файлов.

Для тестов conftest.py задаёт QT_QPA_PLATFORM=offscreen и PYLON_CAMEMU=1;
реальные камеры и BeagleBone тесты не открывают. Предупреждения SWIG о
`__module__` приходят из pypylon и не являются отказом тестов.

Дополнительно проверяются обычный запуск окна через Linux xcb и отдельный
полный путь GUI → pypylon Camera Emulation → Mono12 uint16 TIFF/JSON → Stop →
Close. SDK-эмулятор не моделирует физические входы, реальную пропускную
способность сети и все особенности конкретного ace Classic.

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m louasfm_camera --demo --smoke-seconds 2
./run_linux.sh --demo
```

Загружен полный набор бинарных Windows x64 wheels для Python 3.11 из
requirements.txt и зависимостей. Это проверяет существование подходящих
дистрибутивов; **исполнение на Windows пока не проверено**.

## Проверка на Windows с физической камерой

1. Установить Python 3.11 x64 и pylon с GigE support, создать venv из README.
2. Проверить изображение в pylon Viewer, затем закрыть там устройство.
3. Запустить приложение, найти/выбрать камеру. Записать её модель, серийный
   номер, формат и показанные диапазоны экспозиции/GainRaw.
4. При остановленном захвате сделать «Снять и сохранить». Проверить TIFF/JSON
   и повторный запуск программы с сохранёнными настройками.
5. Проверить free run, ручное сохранение последнего кадра и короткую серию с
   автозаписью. Счётчики полученных/сохранённых должны совпасть после завершения
   дисковой очереди, если каждый полученный кадр записывался ровно один раз.
6. Остановить захват, выбрать доступный 12-битный формат, повторить снимок.
   Проверить диапазон пикселей и uint16 в TIFF. Не считать автоконтраст
   доказательством сохранности исходного динамического диапазона.
7. Подключить проверенный электрический триггер к Line1; выбрать полярность.
   Запустить External без импульсов — окно должно оставаться отзывчивым.
   Подать известное число редких импульсов, сравнить счётчики и файлы.
8. Затем проверить реальную частоту опыта, длительность экспозиции и окно
   освещения rolling shutter; для начала ограничиться короткой записью.
9. Открыть веб-интерфейс BBMain, подключить UDP 9998 и сравнить D0/D2 и фронты
   с осциллографом. Проверить отключение/повторное подключение UDP. Не считать
   последний импульс полной длительностью многостадийного цикла.
10. Закрыть приложение во время записи, проверить завершённые файлы/очередь и
    возможность заново открыть камеру. BeagleBone продолжает свой цикл.

ForceIP проверен на валидацию параметров и наличие метода в SDK, но реальная
перенастройка IP не выполнялась. Физический MAC, сеть, драйвер и разрешения
нужно проверить на стенде. Не требуется менять IP, если камера уже работает.

## Пакет для передачи

После коммита исходников:

```bash
.venv/bin/python scripts/make_release.py --with-wheels
```

Создаются `artifacts/LOUASFM-balser-acA2500-14gm-camera-<commit>.zip` и отдельный
`artifacts/windows-python311-wheels.zip` с SHA-256 файлами. Распакуйте оба в
один каталог: они используют общий верхний уровень с именем проекта. Архив
исходников содержит legacy-код и документацию, но не runtime-конфиг, `.venv`,
снимки, кэши или Git-служебные данные. RELEASE.json хранит исходный коммит.
Полная Git-история остаётся в рабочей папке репозитория.
