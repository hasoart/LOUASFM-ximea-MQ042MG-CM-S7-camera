# XIMEA MQ042MG-CM-S7: особенности для этого опыта

Источник — [страница указанной модели](https://www.ximea.com/products/usb-vision-industrial/xiq-usb3-compact-cmos-cameras/cmosis-cmv4000-spartan-7-usb3-mono-compact-camera)
и [официальный technical manual xiQ-S7 v260902](https://www.ximea.com/downloads/documents-downloads/xiq-s7-usb3-vision-compact-cameras_technical-manual-dwl_manual-pdf).
Проверено 08.11.2026. Суффикс **S7** существенен: это не универсальная
распиновка всех камер с CMV4000.

## Сенсор и битность

CMOSIS CMV4000: моно, 2048×2048, global shutter, физический пиксель 5.5 мкм.
Масштаб на объекте зависит от увеличения оптики и режима считывания; старые
11.775/2.2 мкм и калибровочные коэффициенты других камер сюда не переносятся.
Global shutter экспонирует строки одновременно, но задержки входа,
чтение кадра, повторный запуск и световой импульс всё равно требуют проверки.

У модели **10-битный АЦП**. `Mono16`/`Raw16` — 16-битный контейнер результата,
а не 16 бит физической точности. Доступные в приложении форматы:

| Формат UI | xiAPI | Применение |
| --- | --- | --- |
| Mono8 | XI_MONO8 | Быстрый просмотр, обработка SDK допустима |
| Mono16 | XI_MONO16 | Моноизображение в uint16 с цепочкой SDK |
| Raw8 | XI_RAW8 | Данные без host image processing, 8-битный результат |
| Raw16 | XI_RAW16 | Данные без host image processing, uint16-контейнер |

После установки imgdataformat xiAPI автоматически меняет некоторые параметры
битности. Драйвер задаёт требуемый sensor_bit_depth/output_bit_depth после
формата и читает фактический `image_data_bit_depth` в метаданные. Для uint16
нельзя автоматически считать диапазон 0…65535 или переносить old gain/raw
коэффициенты. Файл содержит числовые значения, возвращённые SDK, без
автоконтраста/нормализации. Камерный timestamp хранится в микросекундах
`tsSec*1e6+tsUSec`, в JSON есть unit; это часы камеры, не UTC ПК.

## Экспозиция, gain, HDR, ROI

- Экспозиция задаётся целым числом микросекунд; 1000 мкс = 1 мс. Заявленный
  диапазон модели — от 26 мкс до 1 с; действующий min/max/inc читается из SDK.
- Gain задаётся в **дБ**, минимум выбирается из камеры. Это не GainRaw Basler.
- В приложении используется FRAME_START с фиксированной программной
  экспозицией. Выбор RisingEdge/FallingEdge определяет запускающий фронт;
  ширина импульса не используется для задания экспозиции.
- Auto exposure/gain выключается (`aeag=0`), HDR выключается при поддержке.
  Для воспроизводимого линейного опыта HDR не включён отдельной кнопкой:
  кусочно-линейная характеристика потребовала бы отдельной калибровки.
  Gamma по возможности задаётся 1.0; Raw-форматы обходят host processing.
- Ноль ширины/высоты — полный допустимый размер; offsetX/offsetY и размер
  выравниваются по шагам устройства. После смены readout/binning диапазоны
  запрашиваются заново. В таблице S7 для MQ042 на полном сенсоре приведён
  readout 1×1: не следует ожидать наличия 2×2/3×3/4×4. Запрошенный
  неподдерживаемый режим вызывает ошибку, а не молчаливую замену.

## USB3 и реальная скорость

Питание и изображения — по USB3, у стандартного корпуса разъём Micro-B.
Используйте качественный SuperSpeed-кабель, исправный USB3-порт и достаточное
питание; не начинайте проверку с пассивного хаба и длинной цепочки устройств.
IP камеры не нужен. При USB2 совместимости не ожидайте рабочей скорости USB3.
USB root controller может быть общим у нескольких внешних портов.

По таблице 32 руководства, стр. 33, при bandwidth limit 380 MB/s для полного
2048×2048 приводятся:

| Transport bits/px | Частота измерения производителя |
| --- | --- |
| 8 | 90.3 FPS |
| 10 | 71.5 FPS |
| 12 | 45.2 FPS |

Sensor bits/px в этих строках — 10. Это разные transport-режимы; надпись
«90 FPS» не обещает 90 FPS для каждого формата и настроек этой программы.
Packing/USB controller/экспозиция/ROI/диск изменяют доступную частоту.
Для первой записи поставьте **10 FPS** и короткую серию; затем измеряйте.
Лимит FPS не исправляет слишком частые внешние триггеры: они могут отвергаться.

Полный uint8 кадр занимает 4 MiB, uint16 — 8 MiB. Уже 50 кадров/с uint16
требуют примерно 400 MiB/s несжатой записи, кроме JSON/обработки. На 90 FPS
это 720 MiB/s. TIFF сохраняется без потери значений, PNG требует дополнительного
CPU на сжатие. Внешний/сетевой диск может не успевать.

Программа использует FIFO (`recent_frame=0`), safe buffer и очередь SDK до
16 буферов; очередь записи — 8 кадров. При переполнении/ошибке диска или
разрыве nframe между принятыми кадрами серия останавливается с сообщением.
Пропущенный до начала сравнения кадр или отвергнутый ещё сенсором физический
триггер этим не гарантированно обнаруживаются. Для строгого учёта всех
импульсов нужно отдельно сравнить осциллограф/счётчики устройства/файлы.

## Триггер: S7 Binder/M5

Руководство S7, стр. 48 (для стандартного корпуса):

| Контакт | Назначение |
| --- | --- |
| 1 | GPIO_GND, общий оптоизолированных входа/выхода |
| 3 | IN, GPI index 1 |
| 4 | OUT, GPO index 1 |

Разъём: Binder 09 3105 81 03, ответная часть по руководству — Binder
77 3550 0000 40003-0x000. Определяйте нумерацию по рисунку производителя,
а не положению строк таблицы или цвету неизвестного кабеля. Для версии FL/FV
используется другой интерфейс/распиновка.

Электрические уровни входа, стр. 50:

- LOW: напряжение <2 В / ток <0.5 мА.
- HIGH: напряжение **>4 В / ток >2 мА**.
- Максимальное входное напряжение: 24 В DC.

GPIO BeagleBone 3,3 В недостаточен для заявленного HIGH. Нужен проверенный
согласующий драйвер/интерфейс, способный обеспечить требуемые уровни и ток
на входе камеры. Не подавайте выходные 5/12/24 В на GPIO BeagleBone.
Схему подключения к вашему стенду нужно проверить до аппаратной пробы;
одной программной настройки GPI1 недостаточно.

По руководству типовые задержки при VINPUT=10 В: rising 1.7±0.2 мкс,
falling 10.7±0.2 мкс. Эти значения нельзя автоматически переносить на другой
уровень/драйвер/кабель. В таблице указан **Input debounce filter: NO**, хотя
общая страница семейства упоминает debouncing: не полагайтесь на наличие
фильтра у данной модели без проверки. В приложении настройка debounce
не предлагается.

Драйвер выбирает `gpi_selector=XI_GPI_PORT1`, `gpi_mode=XI_GPI_TRIGGER`,
`trigger_selector=XI_TRG_SEL_FRAME_START` и соответствующий edge source.
Software использует `XI_TRG_SOFTWARE` и команду trigger_software=1.
Free run — `XI_TRG_OFF`. Обычное ожидание XI_TIMEOUT не завершает захват;
ошибки USB, доступа и драйвера не маскируются под ожидание импульса.
