# LOUASFM — XIMEA MQ042MG-CM-S7 / CMV4000 USB3

Отдельная версия программы для монохромной **XIMEA MQ042MG-CM-S7** по
[указанной странице производителя](https://www.ximea.com/products/usb-vision-industrial/xiq-usb3-compact-cmos-cameras/cmosis-cmv4000-spartan-7-usb3-mono-compact-camera).
Сенсор CMOSIS CMV4000, 2048×2048, global shutter, интерфейс USB3.
Версия Basler сохранена в соседней папке `LOUASFM-balser-acA2500-14gm-camera`.
У копии своя Git-история, venv, настройки и архивы; исходный коммит ответвления
Basler — `f651ea4`. Старые анализаторы/сканеры остаются в `legacy/` для будущего
переноса и не загружаются приложением.

Возможности: просмотр, настройка экспозиции/усиления/ROI/формата/триггера,
одиночный снимок, серия TIFF/PNG с JSON, ROI анализа и профили, наблюдение
схемы текущего ThuliumBB по UDP 9998. Есть демонстрация без SDK и камеры.
[Инструкция в браузере](docs/START_HERE.html), [особенности камеры](docs/CAMERA.md),
[SDK и драйверы](docs/SDK_SETUP.md), [проверки](docs/TESTING.md).

## Важное отличие триггера S7

По руководству именно xiQ-S7 для логической 1 нужен вход **выше 4 В и ток
выше 2 мА**. Прямой GPIO BeagleBone 3,3 В этому требованию не соответствует.
Нужен подходящий согласующий драйвер, например для формирования проверенного
5-вольтового сигнала на стороне входа камеры. Нельзя подавать 5 В на GPIO
BeagleBone. У S7 другой разъём, чем у Basler: Binder/M5, контакт 1 — I/O GND,
3 — IN, 4 — OUT. Проверьте ориентацию по рисунку и точный суффикс камеры;
для старого MQ042MG-CM без S7/вариантов FL распиновку нельзя переносить автоматически.
См. [подключение](docs/CAMERA.md) и [официальный PDF, стр. 48–50](docs/manufacturer/xiq-s7-technical-manual.pdf#page=48).

## Windows: установка один раз

Рекомендуется **Windows 10/11 x64, Python 3.11 x64**.

1. Установите **XIMEA Windows Software Package**, выбрав драйвер USB3/xiQ,
   xiAPI, **xiAPI Python v3**, xiCamTool и xiCOP. Проверена структура официального
   установщика LTS **4.34.00** от 28.10.2026. Скачать:
   [страница XIMEA](https://www.ximea.com/software-downloads).
   В подготовленной рабочей копии установщик также находится в
   `vendor/sdk/XIMEA_Windows_SP_Stable.exe`; он включается в отдельный архив
   SDK и wheels. Запустите его от администратора, примите условия производителя
   и при запросе перезапустите Windows. Приложение само драйверы не устанавливает.
2. Подключите камеру к USB3, проверьте её в xiCOP / xiCamTool. После проверки
   остановите захват и закройте камеру в этих программах: устройством должен
   владеть один контроллер.
3. Откройте PowerShell в папке этой версии:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe scripts\configure_ximea_sdk.py --sdk-root "C:\XIMEA" --check
   .\.venv\Scripts\python.exe -m louasfm_camera
   ```

Если SDK установлен в другом каталоге, замените `C:\XIMEA`. Можно указать
непосредственно папку `API\Python\v3`, содержащую `ximea`. Команда регистрации
проверяет наличие официального `ximea/xiapi.py`, записывает путь только в
`state/ximea-sdk-path.txt` проекта и при `--check` проверяет загрузку DLL и
число камер. Она не исправляет и не копирует код SDK, не меняет системный PATH
и не устанавливает драйвер. Приложение также ищет стандартный `C:\XIMEA`,
`C:\Program Files\XIMEA` и переменную `XIMEA_SDK_ROOT`.

**Одного pip install недостаточно для физической камеры.** requirements.txt
содержит GUI/NumPy/запись; официальный модуль `ximea` и его native-библиотеки
берутся из SDK. Случайные PyPI-перепаковки `ximea-py` не требуются.
Подробнее: [SDK_SETUP.md](docs/SDK_SETUP.md).

Следующие запуски — двойной щелчок по `run_windows.bat` либо:

```powershell
.\.venv\Scripts\python.exe -m louasfm_camera
```

Активация venv необязательна. Для проверки GUI без камеры/SDK:

```powershell
.\.venv\Scripts\python.exe -m louasfm_camera --demo
```

Для установки Python-зависимостей без сети распакуйте архив SDK/wheels поверх
архива исходников и используйте вместо обычного pip:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links vendor\wheels\windows -r requirements.txt
```

Полный установщик XIMEA запускается отдельно. В этой версии не нужны pylon,
ForceIP, IP камеры и настройки сетевой карты для переноса изображений: камера
подключается по USB3. IP BeagleBone по-прежнему нужен для его UDP-мониторинга.

## Linux

В подготовленной рабочей копии собственный venv уже создан:

```bash
./run_linux.sh --demo
```

На другой машине:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m louasfm_camera --demo
```

Для реальной камеры установите официальный **XIMEA Linux Software Package**
по [инструкции производителя](https://www.ximea.com/support/wiki/apis/XIMEA_Linux_Software_Package),
включая native-библиотеки, правила доступа к USB и Python-модуль. Затем:

```bash
.venv/bin/python scripts/configure_ximea_sdk.py --sdk-root /opt/XIMEA --check
.venv/bin/python -m louasfm_camera
```

Уточните фактическую папку установки; `/opt/XIMEA` — стандартный вариант.
Официальный Python SDK 4.34 на Linux загружает `/usr/lib/libm3api.so.2`:
одной распаковки архива в venv недостаточно. Файлы производителя программа
не патчит. На этом компьютере системный SDK не устанавливался: проверена
загрузка native-библиотеки напрямую и перечисление устройств, а GUI работает
без неё через демонстрационный драйвер.

Для Qt/xcb на Ubuntu могут понадобиться `libxcb-cursor0`,
`libxkbcommon-x11-0`, `libegl1`; PySide6 6.12 требует современный Linux
x64 с glibc ≥ 2.34. Все реальные права доступа к USB настраиваются установщиком
SDK/средствами ОС, а не запуском основного приложения через sudo.

## Камера, снимки и запись

1. Выберите **XIMEA / xiAPI (USB3)**, нажмите **Найти**, выберите серийный номер,
   затем **Подключить**. Поиск не открывает и не перенастраивает камеры.
2. Начните с binning 1, ширины/высоты 0 (весь сенсор), смещений 0,
   экспозиции 1000 мкс = 1 мс, усиления **Минимум камеры**, АЦП 10 бит.
   `Mono8` удобен для первой проверки; `Raw16` — для сохранения значений без
   обработки яркости в SDK. У сенсора 10 значащих бит: uint16-файл не делает
   его 16-битным сенсором.
3. **Применить** записывает параметры в остановленную камеру. **Запуск** тоже
   применяет текущие поля. Допустимые диапазоны читаются из SDK; см. подсказки.
   Размеры/экспозиция округляются вниз по допустимому целому шагу, фактические
   значения возвращаются в UI. Если настройка не поддерживается, исправьте
   указанное значение и подключите камеру заново: после частичной ошибки она
   закрывается. Не предполагайте, что модель поддерживает binning 2/3/4 только
   потому, что поле позволяет его выбрать.
4. Выберите каталог, префикс, TIFF или PNG. Основные кнопки есть наверху окна
   и в блоке «Захват и сохранение» ниже настроек.

| Режим / кнопка | Результат |
| --- | --- |
| Непрерывный поток + Запуск | Постоянное получение кадров. Начните с лимита 10 FPS перед проверкой записи полного кадра. |
| Внешний триггер + Запуск | Ожидание импульса на GPI1; выберите RisingEdge/FallingEdge. Отсутствие импульса — нормальное ожидание. |
| Программный триггер + Запуск | Ожидание кнопки «Снять и сохранить». |
| Снять и сохранить, захват остановлен | Применение настроек, временный Software, один снимок, возврат прежнего режима. |
| Снять и сохранить, идёт External | Сохранение следующего кадра от физического импульса без подмены источника триггера. |
| Снять и сохранить, идёт free run | Сохранение следующего полученного кадра. |
| Сохранить последний кадр | Повторное сохранение последнего полученного кадра без новой экспозиции. |
| Стоп | Остановка получения; принятые задания записи дописываются. |

Для серии включите **Сохранять каждый полученный кадр до запуска**. По
умолчанию автозапись выключена. Счётчики/очередь показаны в интерфейсе;
перед отключением диска дождитесь завершения записи. В демонстрации импульс
создаёт **Демо: внешний импульс** — без подключения к BeagleBone.

В TIFF/PNG сохраняются исходные uint8/uint16 от xiAPI; рядом JSON с UTC
приёма, номером кадра, временем камеры в микросекундах, фактической битностью
и цепочкой обработки SDK, настройками и последним контекстом BeagleBone.
Контраст/масштаб/жёлтая ROI анализа не меняют файл. ROI камеры уменьшает сам
передаваемый кадр; ROI анализа меняет статистику и профили.

SDK настроен на FIFO, `recent_frame=0`, safe buffers. Программа обнаруживает
разрыв номеров между принятыми кадрами одной серии, ошибки USB/неполный буфер
и переполнение дисковой очереди; захват останавливается с явной ошибкой.
Это не гарантирует обнаружение каждого пропущенного физического триггера:
камера может отвергнуть импульс до получения кадра. Подробности скорости и
ограничений — [CAMERA.md](docs/CAMERA.md).

## BeagleBone и сохранение настроек

Во вкладке схемы укажите IP платы, например `192.168.1.66`, **UDP 9998** и
реально подключённый канал D0/D2, затем **Подключить BB**. Сначала запустите
BBMain и откройте его веб-страницу `http://192.168.1.66:8081` хотя бы один раз.
Выбор канала только подсвечивает график, а GPI1/полярность относятся к камере.
UDP — мониторинг, физический импульс — запуск экспозиции. Клиент не меняет
выходы платы. Полная длина стадий/хвост 10 мс в UDP не передаются, а привязка
контекста к отдельному кадру приблизительна. См. [BEAGLEBONE.md](docs/BEAGLEBONE.md).

Изменения сохраняются после выбора списка либо Enter/выхода из поля;
проверяйте статус **Настройки сохранены**. Настройки этой копии:
`state/settings.json`, демонстрации — `state/demo.json`, предыдущая версия —
`.json.bak`. Схема конфигурации XIMEA — 2, Basler — 1. **Не копируйте runtime
конфиг Basler:** несовместимая версия отклоняется с сохранением исходного
файла. `--config /полный/путь.json` выбирает отдельный конфиг. Пути по умолчанию
определяются относительно этой копии, а не рабочего каталога терминала.

Закрытие окна / Ctrl+C останавливает камеру и дожидается принятых заданий
записи. BeagleBone продолжает генерировать импульсы. Нештатное выключение
питания/kill процесса не даёт гарантии записи последних файлов.
Ошибки — в «Журнале» и `state/camera.log`. Диагностика без открытия камеры:

```powershell
.\.venv\Scripts\python.exe scripts\diagnose.py
```
